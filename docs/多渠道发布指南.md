# 多渠道发布指南

## 能力范围

| 渠道 | 流程终点 | 已有经验的范围 |
| --- | --- | --- |
| B站 | 上传视频、核对字段、投递并核查回执 | 2026-10-13 实稿投递成功，回执当时为等待审核 |
| 小红书 | 上传视频、核对字段、发布并核查回执 | 同次发布成功页面；用户完成安全扫码 |
| 抖音 | 上传视频、核对字段、提交并检查作品 | 同次已提交，核对到作品记录 |
| 微信视频号 | 上传视频、核对字段、发表并检查作品 | 同次已提交，作品列表有该视频；首次登录由用户扫码 |
| 知乎视频 | 使用视频入口上传、发布并检查详情 | 同次显示发布成功并取得详情链接 |
| 微信公众号 | 排版并保存图文草稿，回读后交用户 | 同次图片、封面、草稿与视频号原生卡片曾验收；**只保存草稿，由用户手动发表** |

上述是原项目的一次历史实测，原始截图和账号状态未随公开仓库提供；不能推断现在仍可用，也不能推断所有作品最终审核通过。新账号和新页面需要重新核验。

## 1. 准备并确认发布包

1. 根据本轮明确要求选择渠道，检查正式成片的时长、画面、声音和内容来源，准备各平台封面。
2. 逐平台准备标题、正文/简介、话题、封面、原创或 AI 声明、分区或合集、账号、可见范围、发布时间；按照平台限制调整。事实与链接必须有来源，不能用默认配置虚构内容或归属。
3. 使用 [发布包模板](../examples/发布包模板.md) 一次展示供用户核对。明确授权该版本后执行；本轮只准备文案时不得发布。账号扫码和安全验证码由用户自行完成。
4. 发布前检查同一账号、平台和成片是否已有任务或作品。历史结果为已提交、审核中或未知时先检查平台，不能为了重新验证流程而重复上传。

## 2. 逐平台执行

1. 检查目标账号与登录状态；超时或窗口关闭不等于登录过期。需要验证时保持原稿，用户自行扫码。
2. 上传正式视频，等待平台处理完成，按发布包填写字段。话题需选择平台提供的真实候选项；正文中的普通 `#文字` 不一定是有效话题。
3. 回读标题、正文、话题、声明、封面、分区及可见范围。图片预览、封面裁剪、上传完成状态都应在页面核对。
4. 在已有授权且字段确认后只提交一次，记录平台回执。平台步骤和历史页面注意点见 [平台操作细节](平台操作细节.md)。
5. 微信公众号执行草稿流程：核对账号、正文图片、标题、摘要、封面和声明。需要插入视频号作品时，在编辑器中选择原生视频号卡片；文本短链不能视为卡片。保存并回读后交用户手动发表，不自动发表或群发。

## 3. 核对与恢复

- 每平台记录结果、时间、账号、作品号或链接、回执来源与待办；可记录成片 SHA-256 以防重复。区分“已提交”“审核中”“已公开”和“结果未知”。
- 如果提交后页面没有明确成功信息，标记为结果未知，先只读检查原稿、作品列表和审核状态；禁止重复提交。用户手动接管后以实际操作和可核实回执为准。
- 一个渠道成功，其他渠道失败时，只继续未完成的渠道。保留已有页面与当前草稿；字段出错先检查新页面，避免重启造成再次上传。
- 自动化需维持同一平台页面的所属线程或进程，防止浏览器对象跨线程。平台页面变化时先检查快照并适配，不能依据旧选择器或脚本无异常推断发布成功。

## 凭证与数据

登录态、授权信息、浏览器缓存、平台后台截图、素材、草稿和任务回执可能含敏感内容，放在本机忽略目录并妥善保管。公开仓库只放脱敏方法和示例，不放账号或真实凭证。提交前检查 Git 变更以及已有历史，不能只依赖 `.gitignore`。
