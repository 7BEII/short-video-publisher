# 平台操作细节

下列经验来自 2026-10-13 原项目页面，控件、限制和话题会变化；当前页面与平台规则优先。参考代码见 [适配器说明](../references/adapters/README.md)，命名步骤需要由相应运行时驱动，本仓库未提供该运行时。

## B站

上传后填写标题、简介、标签，核对分区、原创或 AI 声明、合集；按平台入口设置首页 4:3 与个人空间 16:9 封面。普通标签与平台关联话题可能是不同控件，回读实际选择。历史命名流程：`prepare → fill → category_open/category_select → tags_exact → cover_open/cover43/cover169/cover_confirm → submit → receipt`。页面提示稿件投递成功仅代表已投递，审核结果另查。

## 小红书

上传后填写标题、正文，选择真实话题候选、正式封面和适用的 AI 声明并回读。历史流程：`prepare → topics → cover_open/cover_upload/cover_confirm → declaration_open/declaration_select → verify → submit → receipt`。安全验证后保留原稿，先查看笔记管理列表确认是否已提交；无成功回执时不要重发。历史页面发布按钮使用封闭 shadow DOM，布局发生变化应停止并重新核对。

## 抖音

上传后选择话题实体并核对去掉话题后的纯正文，设置横 4:3 与竖 3:4 封面，确认内容声明。历史流程：`prepare → topics_replace → cover_open/cover43/cover_vertical_open/cover34/cover_confirm → declaration_open/declaration_select → verify → submit → receipt`。两种封面都要检查实际预览；React 更新时操作报错先看页面状态，不反复切换。

## 微信视频号

登录后上传视频，检查正文、短标题、话题、位置、声明和封面；竖 3:4 用于个人主页卡片，横 4:3 用于分享卡片。原项目要求短标题 6–16 字，并检查平台当时的可用字符；新限制以页面为准。自动化历史使用专用单线程 worker 和上游腾讯字段方法，**不调用上游自动循环提交**；发表一次后检查作品列表，状态未知先只读核查。位置和原创权益不得从账号默认值推断。

## 知乎视频

区分图文、回答和视频，使用 `https://www.zhihu.com/upload-video` 对应的视频入口。上传后核对标题、正文、话题实体、封面、视频标记、所属领域与公开范围，再提交一次并查看作品详情。历史详情曾为 `/pin/` 路径，不能因为路径不同就认定失败。

历史参考代码的部分话题和“科技互联网”、AI 声明是针对当时作品写死的，不能直接处理任意内容。其 `verify`/`submit` 要求对应任务目录中存在用户确认记录 `approved.json`；`receipt` 只接受 `/zvideo/`，历史 `/pin/` 是通过 `details` 取得。新内容须先修改、核验字段与详情处理，不能直接套用。

## 微信公众号

根据已确认内容准备正文和本地图片，标题单独填写以免正文重复；检查摘要、正文图、封面与适用声明。需要关联已发表视频号作品时，在编辑器中通过“更多 → 视频号”选择原生卡片。保存草稿并回读；正式发表由用户自行完成。

如使用第三方 MCP 或工具，先核对其来源、权限、登录状态和草稿写入能力。不同工具的接口与验证状态各自独立，不能因为历史上另一条流程成功就断言当前接口可用。
